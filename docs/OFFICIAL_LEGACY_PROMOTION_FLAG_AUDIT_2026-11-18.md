# Official vs legacy promotion-flag audit (2026-11-18)

## Result

The CI audit compares the set of draw IDs that contain at least one official raw
prize row with `awardType=1` against the set of legacy draw records whose
`promotion_flag_legacy` field is `true`.

The audit passed in GitHub Actions run
[44258720743](https://github.com/Be90nia/Lottery/actions/runs/44258720743):

- Official prize rows: 33,530.
- Official draws: 2,949.
- Legacy draws: 2,901.
- Official `awardType=1` draws: 141.
- Legacy true promotion flags: 141.
- The two draw-ID sets match exactly; neither side has an unmatched draw ID.
- The promotion audit command exited successfully and is part of the PR CI workflow.

The matching periods are:

- 21039–21059
- 22040–22068
- 23039–23059
- 24030–24062
- 25038–25057
- 26050–26066

This establishes exact agreement between the legacy draw-level flag and the
presence of at least one raw official `awardType=1` row for every draw in the
available overlap. It is stronger than merely observing that both sources
contain 141 promotion draws.

## Source identity observations

The report generated by `scripts/audit_promotion_flags.py` also retains
frequency counts for the observed raw identity tuple:

`(awardType, group, sort, prizeLevel)`.

The raw source schema audit found 1,327 rows with `awardType=1` across 141
draws. Promotion labels include the base/追加 variants of first and second
prizes and promotion rows for lower tiers. The script records the exact
identity-tuple distribution in the CI artifact
`lottery-research-reports` as
`official-legacy-promotion-audit.json`.

No semantic meaning is assigned to `group` or `sort` beyond preserving and
counting their observed values. `prizeLevelNo` and `relatedPrizeLevelNo`
are absent from the 33,530 raw prize objects in this snapshot.

## Interpretation limits

- This is a draw-level flag reconciliation, not a ticket-level eligibility
  audit. The 2026 campaign's ticket purchase threshold and multi-draw ticket
  semantics cannot be reconstructed from a draw-level flag.
- Agreement does not prove that the historical promotion campaigns had
  identical rules, nor does it validate each ticket's entitlement.
- The legacy cleaner omitted upstream prize identity fields. Therefore,
  matching draw-level promotion flags do not restore source identity for the
  33,098 legacy prize rows.
- Snapshot hashes and matching values establish integrity and consistency of
  the archived data, not the authenticity of the draw process.

## Reproduction

CI runs:

```sh
python scripts/audit_promotion_flags.py \
  --official data/processed/prizes-20261118.jsonl \
  --legacy-draws data/candidates/legacy_draws.jsonl \
  --output official-legacy-promotion-audit.json
```

The command exits non-zero if either source has an unmatched promotion draw ID.


## Historical campaign limitation

The exact set match above is specifically between raw API `awardType=1`
draws and the legacy cleaner's draw-level `promotion_flag_legacy`. It is not
an exhaustive audit of every historical campaign described as a promotion.

Issue 17045 is a counterexample to overgeneralizing this result: the archived
API draw has `lotteryPromotionFlag=0` and no `awardType=1` prize rows, while
the contemporaneous Jiangsu result announcement explicitly lists promotion
rows for first through sixth prize. The API prize list does not preserve the
same separate promotion/additional row structure shown on the provincial page.
See [the 17045 announcement](https://www.js-lottery.com/cms/post-77220.html)
and [the API/provincial conflict audit](OFFICIAL_API_PROVINCIAL_PRIZE_CONFLICTS_2026-11-18.md).

Accordingly, the validated claim is narrow: **for the 141 draws represented
as `awardType=1` in this API snapshot, the legacy draw-level flags align
exactly**. This does not validate earlier promotion campaigns or prove that
the API's historical promotion representation is complete.
